EXECUTIVE SUMMARY — v3.0 変更点

v2.0 では Lizard（Python CLI）を使って Cyclomatic Complexity / 関数行数 / 引数数を検知していた。 v3.0 では Lizard を廃止し、eslint-plugin-sonarjs に完全移行した。 SonarJS は ESLint プラグインとして動作するため Python のセットアップが不要になり、 CI の job 数も 10 → 9 に削減。IDE でのリアルタイム検知も同時に実現する。

追加検知能力: SonarJS は Lizard が持たなかった no-identical-functions（コードクローン）・ no-duplicate-string（マジックストリング）・ no-duplicated-branches（条件分岐の重複実装）・ no-ignored-return（副作用なし関数の戻り値無視）等を追加検知できる。

Biome と SonarJS の役割分担 — Cognitive Complexity の二重チェック

Cognitive Complexity は Biome と SonarJS の両方が同じ SonarSource アルゴリズムで測定する。意図的な二重チェック。

  • Biome: CI での高速チェック。noExcessiveCognitiveComplexity が違反を error にする
  • SonarJS: IDE (VS Code) でのリアルタイム表示。コードを書いた瞬間に赤線が出る

どちらも閾値 10 で統一。片方をすり抜けてももう片方が必ず検知する。

DUAL CHECK
SonarJS recommended を使わずピンポイント指定する理由

SonarJS v2 以降は recommended に大量のルールが追加され、Biome / typescript-eslint との重複が発生する。本構成では Biome が担わない領域だけを SonarJS でカバーするため、ルールをピンポイントで指定する。

  • 使わない: sonarjs/recommended 全体 — Biome重複・ノイズが多い
  • 使う: コードクローン / 重複文字列 / 条件分岐重複 / 論理バグ / Cognitive Complexity の13ルール

閾値一覧 — THRESHOLDS 定数で一元管理

eslint.config.mjs の THRESHOLDS オブジェクトを変えれば全ルールに反映される。 チームの議論も「THRESHOLDS.MAX_FUNC_LINES を 60 → 50 にするか」と具体的になる。
定数名値適用ルールレベル根拠
COGNITIVE_COMPLEXITY 10 sonarjs/cognitive-complexity
+ Biome		 error SonarSource 推奨。10超=レビュアー5分以上。Biomeと同値で揃える
MAX_FUNC_LINES 60 max-lines-per-function warn スクリーン1.5画面。超えたら子コンポーネント / カスタムhook に分割
MAX_FILE_LINES 300 max-lines warn 300行超=複数責務混在の可能性大
MAX_PARAMS 4 max-params warn 4超→オブジェクト引数化のサイン。型安全性も上がる
MAX_DEPTH 3 max-depth warn 3超→Early return / Extract Function で対応可能なケースがほぼ確実
MAX_DEPENDENCIES 10 import/max-dependencies warn 10超=多重責務の間接シグナル。型importは除外してカウント
DUPLICATE_STRING_MIN 3 sonarjs/no-duplicate-string warn 同一文字列が3回以上登場→定数に切り出すサイン
IDENTICAL_FUNC_LINES 3 sonarjs/no-identical-functions warn 同一実装が3行以上の関数が複数→関数抽出のサイン (旧Lizard --CPD 相当)

eslint.config.mjs — SonarJS ブロック追加

v3 主要変更
v3 最大の変更点: Lizard（外部CLI）を廃止し、④ SonarJS ブロックを追加。 コードクローン・重複文字列・論理バグを ESLint のエコシステム内で完結させる。
新規 ④SonarJS ブロック — 13ルール ピンポイント指定
// import
import sonarjs from "eslint-plugin-sonarjs";

// ブロック④: SonarJSルール (src/**/*.{ts,tsx})
{
  plugins: { sonarjs },
  rules: {
    // Cognitive Complexity (Biome と同閾値 → IDE でリアルタイム表示)
    "sonarjs/cognitive-complexity": ["error", THRESHOLDS.COGNITIVE_COMPLEXITY],

    // コードクローン (旧 Lizard --CPD 相当・関数単位でより正確)
    "sonarjs/no-identical-functions": ["warn", THRESHOLDS.IDENTICAL_FUNC_LINES],

    // マジックストリング → 定数化のサイン
    "sonarjs/no-duplicate-string": ["warn", { threshold: THRESHOLDS.DUPLICATE_STRING_MIN }],

    // 条件分岐の重複実装 → コピペバグの典型
    "sonarjs/no-duplicated-branches":     "error",
    "sonarjs/no-all-duplicated-branches":  "error",

    // 同一条件式 / 恒真条件
    "sonarjs/no-identical-conditions":   "error",
    "sonarjs/no-identical-expressions":   "error",

    // 論理バグ
    "sonarjs/no-one-iteration-loop":      "error",
    "sonarjs/no-ignored-return":          "warn",
    "sonarjs/no-empty-collection":        "error",

    // 冗長コード
    "sonarjs/no-collapsible-if":          "warn",
    "sonarjs/no-redundant-boolean":       "error",
    "sonarjs/no-redundant-jump":          "warn",
    "sonarjs/max-switch-cases":           ["warn", 10],
  },
}

設計原則

01 / ECOSYSTEM
全ツールを Node.js エコシステムに統一
Lizard (Python) を廃止し、pnpm install だけでセットアップが完結する。CIの job 構成もシンプルになり、onboarding コストが下がる。
02 / DUAL-CHECK
Cognitive Complexity を IDE と CI で二重チェック
SonarJS が IDE でリアルタイム警告、Biome が CI でブロック。書いた瞬間と PR 時の両方で検知するため、複雑な関数がコードベースに入ることを二重に防ぐ。
03 / PINPOINT
recommended を使わずピンポイント指定
SonarJS recommended は Biome / ESLint との重複が多い。必要な13ルールだけを明示的に有効化することで、ノイズを排除しつつ最大の効果を得る。
04 / CONSTANTS
閾値は THRESHOLDS 定数で一元管理
eslint.config.mjs の THRESHOLDS を変えれば全ルールに反映。Biome の閾値と THRESHOLDS.COGNITIVE_COMPLEXITY を常に同値に保つことが重要。
05 / TEST-EXCEPT
テストファイルは SonarJS を適切に除外
テストは同じセットアップを繰り返すことが正当。no-identical-functions / no-duplicate-string をテストファイルで off にすることで誤検知を防ぐ。
06 / LBOSE
8人 × 80社でも機能する自動化
全ゲートが自動実行される。AIエージェントが生成したコードの品質問題を人間のレビュー前に機械が検知することで、8人のエンジニアが80社を安全に支援できる。
